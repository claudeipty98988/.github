<h2>一、下单前的十二个问题，能问住一半供应商</h2>
<p>不用一次问完，按顺序问，对方愿意逐条给具体数字的，基本可以继续谈；只会回"放心，很稳"的，可以直接跳过。</p>
<h3>必问的五个硬指标</h3>
<p>地址归属的 ASN 与运营商名称、这条地址当前是否被他人使用、月流量或带宽上限、并发连接数、故障响应时长。这五项都有可能有明确答案，含糊其辞说明对方自己也不掌握资源。</p>
<h3>后七个属于加分项</h3>
<p>能否指定城市、能否免费更换、更换次数上限、是否提供 API 查询、日志保存多久、是否支持按天计费、账单周期能否调整。这些不影响能不能用，但影响长期用起来顺不顺。</p>

<h2>二、地区这一项要拆到城市和 ASN</h2>
<p>"美国住宅 IP"这句话信息量几乎为零。美国东西岸延迟差一倍，同一个城市里不同运营商的地址段信誉也不同。地区选择至少要到城市一级，最好能看到 ASN。</p>
<h3>先对齐账号资料里的地区</h3>
<p>账号注册时填的城市、支付方式所属国家、常用语言，这三项构成一个地区画像。出口城市和这个画像偏离太远，即便地址本身干净，也会显得不协调。优先选画像里已有的城市，没有就选同国同语区的大城市。</p>
<h3>城市级和 ASN 级的差别</h3>
<p>城市级决定延迟和时区合理性，ASN 级决定这条地址"像不像家庭宽带"。有些地址查归属地显示某市，但 ASN 属于数据中心运营商，这种在风控视角下仍然是机房。查法是在 ipinfo.io 看 org 字段，出现 hosting、cloud、datacenter 一类字样的要谨慎。</p>

<h2>三、带宽单位里的三个坑</h2>
<p>带宽是最容易被打马虎眼的一项。同一句话"100M 带宽"，在不同供应商嘴里可能是三种东西。</p>
<h3>Mbps 不等于 MB/s</h3>
<p>标称 100Mbps 换算成下载速度大约 12.5MB/s，差八倍。问的时候直接问"高峰期实测下载能到多少兆每秒"，让对方给数字而不是给单位。</p>
<h3>共享带宽的峰谷差</h3>
<p>写"共享 1Gbps"的，晚高峰可能只剩几十兆。问清楚这条线路下挂了多少户，以及晚八点到十一点的实测值。拿不到实测值，就要求试用期自己测。</p>
<h3>上下行不对称</h3>
<p>家庭宽带普遍上行小，标 500M 下行的线路，上行可能只有 30M。做 API 调用或上传素材时，卡的是上行。这一项必须单独确认，别被总带宽数字带过去。</p>

<h2>四、共享率是唯一必须落纸的指标</h2>
<p>价格差一大截，八成差在这。共享率指同一条出口地址同时被多少个用户使用，多数供应商不会主动说，但这是决定长期体验的核心变量。</p>
<h3>共享率怎么看</h3>
<p>先问，再自己验。验证方法是连续一周每天固定时段查一次出口的会话特征：如果同一条地址上出现你从未发起的流量特征，或者延迟曲线在固定时段规律性抬升，说明有人和你抢。更直接的办法是看供应商能否提供"本地址当前活跃会话数"。</p>

<h2>五、试用 72 小时该验什么</h2>
<p>试用不是"能打开网页就行"。三天时间刚好覆盖两个工作日加一个晚高峰，按下面的顺序验，能筛掉大部分不合格的线。</p>
<h3>第一天验地址，第二天验稳定，第三天验切换</h3>
<p>第一天确认出口地址、ASN、城市三项与承诺一致，并记录是否变化；第二天跑晚高峰测试，看延迟和丢包；第三天故意重启一次设备，看多久恢复、恢复后地址是否还是原来那条。三步都过，再谈价格。</p>
<h3>试用期就把台账建起来</h3>
<p>开通当天建表，字段包含开通日期、地址、ASN、城市、共享率承诺、带宽、到期日。后面所有沟通都围绕这张表，比口头记忆可靠。换供应商时，这张表也能直接拿来对比。</p>

<h2>常见问答</h2>
<h3>价格差三倍，是不是贵的就一定好？</h3>
<p>答：不一定，但便宜到明显偏离市场价的一定有原因，通常是共享率高、带宽虚标或地址段被大量使用。先问清共享率和带宽，再看价格是否匹配。</p>
<h3>供应商不承诺共享率怎么办？</h3>
<p>答：可以作为风险点记录下来，用试用期自己验证。如果验证下来晚高峰抖动明显，就按不达标处理，不必纠缠承诺文本。</p>
<h3>城市一定要和账号资料一致吗？</h3>
<p>答：同一国家内跨城市通常可以接受，跨国家或跨时区跨度太大就值得注意。支付地区、常用语言、登录时段三者能自洽，比精确到同城更重要。</p>
<h3>带宽买大了会不会浪费？</h3>
<p>答：会。日常网页对话 10Mbps 上下就够，买 200M 只会在账单上体现。把预算放在地址稳定性和低共享率上，比堆带宽划算。</p>
